# ForgeMCP 0.2.3

This release reduces clangd worker pressure and stops retaining analyzed documents
between requests on projects with multiple CMake configurations.

## Changes

- Each clangd process starts with `-j=2`. Sessions still start automatically when
  ForgeMCP starts and when CMake publishes an available compilation database.
- File analysis opens the current full source, collects its result, and closes the
  document before returning, including cleanup after errors and cancellation.
  Saved header changes are incorporated on the next file analysis without
  reopening every previously analyzed file after Workspace mutations.
- Partial Workspace reads analyze the complete file and return only diagnostics
  and semantic spans intersecting the returned lines, with absolute coordinates.
- Explicit clangd tools query only their existing `configurations` selection.
  Workspace enrichment continues to analyze all available configurations.
  No MCP tool parameters were added.
- Added regression tests for document cleanup, stale diagnostic notifications,
  configuration selection, and partial-read annotations.

The worker setting applies per process and does not impose a memory limit.
Clangd processes retain their indexes; repeated file requests require a fresh parse.

## Installation

Requires Python 3.13 or newer:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install forge-cpp-mcp==0.2.3
.\.venv\Scripts\forgemcp.exe --workspace C:\Projects\Example
```

The attached wheel can also be installed directly:

```powershell
.\.venv\Scripts\python.exe -m pip install .\forge_cpp_mcp-0.2.3-py3-none-any.whl
```

On macOS/Linux, use `.venv/bin/python` and `.venv/bin/forgemcp`.
The wheel includes compiled widgets and icons; Node.js is required only for source
builds. Install CMake, compilers, Ninja, and clangd separately as needed.
The attached source distribution includes frontend sources and the npm lockfile;
`SHA256SUMS` covers both packages. Early-development limitations from 0.2.0 remain.
