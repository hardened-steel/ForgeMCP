# ForgeMCP 0.2.5

This release tracks CMake configuration inputs and withdraws outdated clangd
contexts until a successful configure or build-time regeneration confirms them.

## Changes

- CMake requests `cmakeFiles-v1` through the File API and records SHA-256 hashes
  of configuration inputs separately for each managed build directory. Every new
  successful generation replaces that directory's dependency list.
- Workspace writes, edits, moves, deletions, and directory creation check known
  dependencies. Shared input changes invalidate every consuming configuration;
  identical replacements and ordinary source/header edits preserve contexts unless
  those files are configuration inputs. Known preset files and structural changes
  affecting CONFIGURE_DEPENDS globs use conservative invalidation.
- Outdated, unknown, and failed configurations cannot provide clangd contexts,
  even when an old compilation database still exists. CMake publishes independent
  snapshots through its existing subscription; clangd closes only affected sessions
  and preserves sessions whose context and database contents are unchanged.
- Builds remain available for outdated configurations. A new successful File API
  generation restores contexts even if subsequent compilation fails. Successful
  builds without regeneration cannot adopt a new input baseline, and failed
  generation cannot reactivate old artifacts.
- Analysis errors explain that inputs may be outdated or unconfirmed and direct
  the caller to `cmake_configure`. Error and cancellation paths release captured
  locks and conservatively withdraw configurations whose freshness is uncertain.
- Added backend and MCP protocol regression tests for dependency updates,
  invalidation, build regeneration, independent profiles, subscription ordering,
  session reuse, and failure/cancellation cleanup.

Tool names, resource URIs, and existing result fields are unchanged. No new tools
or Git module are introduced.

## Tracking boundaries

Baselines live in memory. After restarting ForgeMCP, run `cmake_configure` before
using confirmed clangd contexts; preexisting File API replies and compilation
databases alone are insufficient. Invalidation preserves build trees and databases
and does not automatically configure projects.

Checks occur only during controlled Workspace mutations, configure, and build.
There are no filesystem watchers, polling, background scans, or guarantees about
external editor/process changes. Hash tracking includes `project/` and `storage/`
inputs only; external `root/` inputs are excluded without reads or elicitation.
ForgeMCP does not parse CMake, resolve preset inheritance/includes, or reproduce
CMake glob matching. Older File API replies without glob information conservatively
invalidate configurations on structural changes.

## Installation

Requires Python 3.13 or newer:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install forge-cpp-mcp==0.2.5
.\.venv\Scripts\forgemcp.exe --workspace C:\Projects\Example
```

The attached wheel can also be installed directly:

```powershell
.\.venv\Scripts\python.exe -m pip install .\forge_cpp_mcp-0.2.5-py3-none-any.whl
```

On macOS/Linux, use `.venv/bin/python` and `.venv/bin/forgemcp`.
The wheel includes compiled widgets and icons; Node.js is needed only for source
builds. Install CMake, compilers, Ninja, and clangd separately as needed.
The source distribution includes frontend sources and the npm lockfile;
`SHA256SUMS` covers both packages. Early-development limitations remain.
