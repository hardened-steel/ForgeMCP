# ForgeMCP 0.5.1

This patch release preserves healthy clangd sessions during Git metadata changes
and restores MCP widgets when chat history retains a complete JSON result.

## Fixes

- Preserve clangd sessions and confirmed CMake contexts across staging, unstaging,
  commits, same-tree branch changes, fetch, and push when working-file structure
  and CMake inputs are unchanged. This includes failed `nothing to commit` attempts.
- Compare physical path existence and types before and after Git mutations.
  Actual structural changes still invalidate dependent configurations, while
  content changes notify retained sessions. Failed hooks, cancellation, and
  unavailable verification retain conservative invalidation and process provenance;
  verification failures do not conceal completed commits.
- Recover missing or null `structuredContent` from exactly one complete JSON
  object retained in text content, including JSON or unlabelled Markdown fences.
  The shared widget bridge and the separate process-details widget use the same
  recovery before rendering and linked-resource loading. Existing structured
  results and tool errors keep precedence; malformed or ambiguous content stays
  in the text view.

Git snapshots include at most 100,000 distinct paths within the existing output
budget. Ignored-only changes and empty directories outside the Git-visible
catalog remain untracked. Widget recovery requires retained JSON: readable plain
text alone cannot reconstruct a structured result, and linked in-memory resources
remain unavailable after their owning server restarts.

## Installation

Requires Python 3.13 or newer. Install the attached wheel:

```powershell
python -m pip install forge_cpp_mcp-0.5.1-py3-none-any.whl
```

The PyPI package can also be installed with:

```powershell
python -m pip install forge-cpp-mcp==0.5.1
```

The wheel contains compiled widgets, the administration panel, and icons. Node.js
is required only for source builds. Install CMake, compilers, clangd, LLDB-DAP,
and other development tools separately as needed. The source archive includes
frontend inputs and the npm lockfile; `SHA256SUMS` covers both distribution files.
