# ForgeMCP 0.5.0

This release adds native debugging through LLDB-DAP, prepares CMake configurations
in the background at startup, and improves tool errors and administration controls.

## Changes

- Launch native programs, attach to explicit local process IDs, and inspect
  user-mode crash dumps through a selected LLDB-DAP toolset. The 22 debugger tools
  cover source/function/exception breakpoints, execution control, bounded waiting,
  threads, stacks, scopes, variables, modules, exceptions, memory, and disassembly.
- Keep debugger session phase, target execution state, and stop/exit/failure details
  explicit. Execution receipts retain subsequent outcomes; frame, variable, and
  memory references expire when execution resumes. A wait timeout leaves the
  target running, and an uncertain control command is never automatically repeated.
- Close launched targets by terminating them, attached targets by detaching, and
  dumps by releasing inspection resources. Close results distinguish physical
  adapter closure from confirmed or unknown target disposition. Initial source
  breakpoint paths are checked before target launch.
- Package a debugger result widget, icon, typed results, readable text, and progress
  notifications. Debugger tools are available to MCP clients; the admin bridge
  excludes them from its command catalog and rejects direct debugging calls.
- Configure all effective CMake profiles once in the background after toolchain
  discovery and clangd subscription setup. Requests remain available, successful
  contexts are published after each profile, and startup outcomes are retained in
  the CMake monitor. Shutdown cancels and awaits startup work before closing services.
- Identify invalid JSON parameters and missing prerequisites in expected tool
  errors, with concrete corrections, bounded available choices, and existing
  discovery calls. Unknown top-level arguments are rejected with spelling hints.
  Process IDs and transcript hints survive command failures; errors distinguish
  unstarted operations, partial mutations, uncertain outcomes, and secondary
  synchronization failures without echoing private arguments or adapter payloads.
- Generate admin command fields from tool schemas while retaining complete JSON
  input. Resource-template fields use native MCP completions with other entered
  parameters as context. The completion bridge also accepts prompt references.
- Fix EOF handling when a fast process closes an empty stdin before the server
  handles its queued close. Pending input and final encoder-byte failures still
  produce process errors.

Install LLDB-DAP in a discovered toolset or configure it with
`--toolset NAME lldb-dap=PATH`, then call `debugger_adapters` to find the available
toolset and adapter IDs. Debugging uses existing binaries and does not rebuild
them or require a CMake compilation database. Source locations remain unverified
against the loaded binary; external source files are not read automatically.
Each runtime retains at most 128 sessions, including closed sessions, and the
last 64 execution observations per session. Restart the server to release history.

## Installation

Requires Python 3.13 or newer. Install the attached wheel:

```powershell
python -m pip install forge_cpp_mcp-0.5.0-py3-none-any.whl
forgemcp --workspace C:\Projects\Example
```

The PyPI package can also be installed with:

```powershell
python -m pip install forge-cpp-mcp==0.5.0
```

The wheel contains compiled widgets, the administration panel, and icons. Node.js
is required only for source builds. Install LLDB-DAP, CMake, compilers, and other
development tools separately as needed. The source archive includes frontend
inputs and the npm lockfile; `SHA256SUMS` covers both distribution files.
Existing early-development limitations remain.
