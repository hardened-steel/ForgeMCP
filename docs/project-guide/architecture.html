Архитектура

Слои строят границы, а не бюрократию

В каждом слое есть только одна причина меняться. Благодаря этому добавление нового инструмента C++ обычно означает новый плагин, а не изменение сервера, MCP-протокола и всех остальных возможностей.

Направление зависимостей

Стрелка направлена от использующего слоя к используемому. Внешние протоколы остаются на краю; между предметными модулями проходят только собственные модели и небольшие события.

Общие сервисы — «инфраструктурная шина»

ServiceRegistry

Именованный контейнер зависимостей. Core создаёт его и явно кладёт туда объекты; модули берут только нужные службы. Это делает связи видимыми и тестируемыми.

WorkspaceService

Единственный доверенный путь чтения и записи файлов. Проверяет, что путь остаётся в рабочей папке, и публикует безопасные события об изменении.

ProcessRuntime

Единая граница запуска программ: argv без shell, лимиты, тайм-аут, отмена, сбор ограниченного вывода и завершение дерева процессов.

ToolchainDiscoveryService

Один раз выбирает утверждённые executable-файлы и, для MSVC, фильтрованное developer environment. Остальным модулям не приходится искать PATH.

StructuredLogger

Пишет только разрешённые метаданные в stderr, кольцевой буфер и при необходимости MCP. Содержимое файла, argv и секреты отсекаются.

ProjectStatusRegistry

Собирает кэшированные безопасные факты о компонентах. Статус не запускает сборку, не читает исходники и не обновляет интеграции.

Неявные на первый взгляд, но важные связи

Workspace → CMake → clangd

После успешной правки Workspace публикует content-free событие. CMake помечает профиль устаревшим, если изменился CMake-вход. clangd синхронизирует отслеживаемый документ. Когда CMake нашёл новую корректную compilation database, clangd может контролируемо перезапуститься.

Разобрать цепочку →

Core → плагины → статус

Плагины при запуске регистрируют свои инструменты и провайдеры статуса. Project-плагин лишь агрегирует уже имеющиеся кэши: его ответ специально нетранзакционный, но безопасный и быстрый.

Открыть Project →
Правило архитектуры. Нельзя «срезать угол» и передать тип LSP/DAP/MCP из адаптера в доменную модель. Это удерживает ядро и плагины независимыми от конкретных библиотек и протоколов.
